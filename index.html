Install or update

  • Put the three files in one folder and check the kit (the first commands below). Then run the script as your normal user (not as root). The script asks for your password once, at the start.
  • Updating: Run the script again with the new kit file. It stops the running PGGB, moves the old ~/pggb aside and starts the new one. Updates keep your Direct Ethernet setting and check the PGGB Bridge.
  • Running it again is safe: it repairs a setup left half done.

Get the kit and check it

curl -LO https://github.com/remastero/pggb-lx-0gaebd/raw/main/pggb-linux-9.1.48.tar.gz
curl -LO https://github.com/remastero/pggb-lx-0gaebd/raw/main/pggb-linux-9.1.48.tar.gz.sha256
curl -LO https://github.com/remastero/pggb-lx-0gaebd/raw/main/install_pggb.sh
sha256sum -c pggb-linux-9.1.48.tar.gz.sha256

Install or update, starting PGGB at every boot

chmod +x install_pggb.sh
./install_pggb.sh --boot pggb-linux-9.1.48.tar.gz

Notes for your setup

Roon and the PGGB Bridge

In Roon, the PGGB Bridge shows as two ALSA devices, both named "Loopback PCM", with no other detail. Either one works: enable one of them and give it a name such as "PGGB Bridge" in Roon's settings for that device.

Details
  • In PGGB-Live, choose the input "Device Input (PGGB Bridge)", press Play, then start the player.
  • In your player, choose the device pggb_bridge (PGGB Bridge), or hw:CARD=PGGBBridge,DEV=0. Do not choose plughw:, default or dmix: they can change the audio before PGGB gets it.
  • If you use ALSA's loopback card for something else, the script keeps your card, with its number and name, and makes the bridge a second one.

Direct Ethernet

This kit has Direct Ethernet. Updates keep your Direct Ethernet setting.

Details
  • PGGB's own switch, Allow Direct Ethernet, is with the PAL endpoint's settings and is on by default.
  • A cable straight from this computer to the endpoint has no DHCP server: give both ends fixed addresses in the same range (for example 10.0.0.1 and 10.0.0.2, mask 255.255.255.0). PGGB looks for endpoints on every network port. If the endpoint is not listed, type its address in "PAL host or address" (the Output devices gear panel, with PAL selected) and press Enter. A firewall on this computer must allow UDP from the endpoint.
  • --no-direct-ethernet disables it again. --remove removes it along with PGGB.

The web Remote

Open http://<this computer's address>:8180/ in a browser on the same network. The script prints the addresses PGGB reports; later, tail ~/pggb/logs/pggb.out shows them again. If a firewall runs, allow TCP port 8180 from the local network.

Every day

Stop: systemctl --user stop pggb. Start: systemctl --user start pggb.

Details
  • With Direct Ethernet: sudo systemctl stop pggb and sudo systemctl start pggb.
  • PGGB's output: ~/pggb/logs/pggb.out. The script never touches your settings (~/.config/pggb) or PGGB's data (~/PGGB), not even with --remove. Delete them yourself for a clean start.

New since your last kit (24 November)

Dynamic Range Expander and DR

The status line says what the Expander does on each track, and a DR badge in the player shows what it did on the playing track. The badge appears only when a track needs it; hover over it for the details.

Details
  • The Library shows each track’s DR (dynamic range), for example DR7 → 9 where the Expander changed it, and you can sort by it. History shows each play’s DR with what the Expander did, in short: for example DR7 → 9 CL(F), where C is clipping repaired, L limiting undone, and (F) or (L) the Full or Lite repair. Hover over it, or tap it on a touch screen, for the details. An album’s tracks show the same letters under their DR, from each track’s latest play.
  • DSD tracks get their DR too: the Library measures them in the background while nothing plays, about a minute for a five-minute DSD64 track. The → of what the Expander changed is not shown for DSD tracks yet.
  • With Allow expansion of DSD tracks on, the Expander also works on DSD tracks in Live; Always de-limit does not apply to them yet. A track whose peaks look clipped but cannot be repaired is left unchanged, and the status line says so.

The Library on the Remote

Backups: choose a folder, then back up the Library now or every day at a set time, and choose how many backups to keep. Restore checks a backup first, asks where your music is now if its folders have moved, and asks you to confirm.

Details
  • The Play queue on the Remote has Remove from queue, Move earlier and Move later, as in the app.
  • Folders: Refresh scans the folder shown.
  • After an update, the Library shows its progress once: Updating your library for this version of PGGB, with the albums done so far. It waits while PGGB plays.
  • The Library's player bar shows the volume in dB.

Fixed since your last kit

If you saw any of these, they are fixed now:

The 6 fixes
  • The Remote's Library stayed on Opening… when PGGB had been idle.
  • After a seek while playing to a PAL endpoint, the progress bar, the time, the waveform and the title lagged behind the music.
  • When the player feeding Device Input (the PGGB Bridge) stopped, PGGB counted the music as running dry.
  • On a phone's browser, the keyboard closed while typing in a field on the Remote.
  • Add folder under Storage disappeared under the pointer on the Remote.
  • On the Remote, the mark on the playing track in the Library stood still on a computer or phone set to reduce motion. It now moves, as in the app.

Reporting a problem

  • On the Remote, in Settings > Live > Logs and statistics, turn on Log diagnostics, reproduce the problem, then send us ~/pggb/logs/pggb.out and the newest pggb_live_….log from ~/PGGB. Turn diagnostics off when you are done.
  • Stealth stops every log, so turn it off before you reproduce a problem.
  • Please include the format and rate of the music you played, your output (the PAL endpoint or the DAC), and what happened.
